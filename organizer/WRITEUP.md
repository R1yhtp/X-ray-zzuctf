# X-ray 官方解法与出题说明

## 机制与边界

这是显示控制器的历史重建题。参赛者观察的是 DMA 引脚，不是秘密 ROM。
前台 bank0 驱动 `pixel`，后台 bank1 承载维护图案，随后被 scrub 清零。
必须从合法写入历史中重建“曾经存在的状态”，保存正确时刻的画面。

在线改编增加了四通道仪器配置、多次确定性重放、跨采集时间对齐、
ready/valid 背压、按字节写入以及平铺蛇形显存布局。这些步骤服务于同一个
显存重建问题。全部关键规则在公开 RTL 和板卡手册中，没有外部未知密钥。

flag 由启动时 `GZCTF_FLAG` 整体栅格化到 192×64 点阵，再通过 ROM 端口进入 RTL。
服务器中的私有 ROM 不下发；HTTP 响应和前端源码不含真实字符文本。

## 1. 看清可观测面

`display_core.sv` 定义两组显存，`pixel` 始终读 bank0。
DMA 的 `tx_bank` 固定为 1，因此采集最终视频只能得到前台测试图案。
`phase` 在 clear、draw、scrub 后进入 done；没有把维护图案切到前台的步骤。
这解释了题面中的“一闪而过”和“屏幕没留下”。

## 2. 对齐两组采集

控制组：`tx_valid, tx_ready, tx_bank, tx_mask`。
数据组：`tx_addr, tx_data`。
均选 `activity`，起始事件依次为 0、1024、2048、3072，深度 1024。
每次都从同一实例的同一上电状态重新运行，因此两组采样时间戳一致。

当前 RTL 的 activity 窗口总计 4095 条候选事件。官方脚本从元数据读取总数，
不会假设所有请求都能采满。总共八次 API 请求，得到完整控制和数据历史。

采样点在 DUT 的下一次上升沿之前，表示待处理事务。解析 VCD 时先处理同一时刻的
探针赋值，再在 `sample=1` 处生成记录，避免错误使用上一条的值。

## 3. 只应用真正完成的事务

条件为 `tx_valid && tx_ready`。activity 触发仅筛 `tx_valid`，仍包含背压等待。
三阶段共 3072 次成功写入：clear 768，draw 1536，scrub 768。

draw 每个 word 分两次写入。`tx_mask[0]` 控制低 8 位，`tx_mask[1]` 控制高 8 位；
未使能的另一半含总线残留 `d3` 或 `6b`，必须保留原显存对应字节。
直接把 `tx_data` 覆盖整个 word 会产生错误点阵。

## 4. 保存擦除前快照

完成第 `768 + 2*768 = 2304` 次握手写入时，draw 刚结束。
复制 bank1，然后继续重放剩余记录。最终 bank1 应全部为 0。
最终值与历史快照的差异是题目的核心。

## 5. 逆显存布局

画面共 12 个 word 列，每个 word 覆盖 16 个水平像素。
tile 为 16×8；每个奇数 tile 行的 tile 列倒序布线。

对像素 `(x,y)`：

```python
word_col = x // 16
tile_x = 11 - word_col if (y // 8) & 1 else word_col
address = ((y // 8) * 12 + tile_x) * 8 + y % 8
pixel = (bank1[address] >> (x % 16)) & 1
```

从内存还原点阵后可直接阅读 flag；自动解法使用附件 `font5x7.json` 识别字形。
字库公开是为了避免把字体识别变成题目难点。字符原点 `(6,14)`、每行 30 字、
横向步进 6 像素、纵向步进 10 像素均记录在板卡资料中。

## 复现

```bash
python3 organizer/solve.py http://127.0.0.1:8000 --out recovered
```

该脚本只请求公开附件和采集接口，不访问服务器文件、环境变量或内部 Python 模块。
输出恢复图、最终清空图、原始波形、解题报告和实际动态 flag。
完整 flag 不在本文中写死；本地演示 flag 只用于测试。

## 非预期解审查范围

- 任意层次路径不可作为探针；只允许固定的十二种公开总线及扫描信号。
- 不接受 RTL 上传或自由编写触发代码；采集参数为受限数字和枚举。
- 不提供磁盘文件路径接口；静态路由采用固定允许清单。
- 子进程参数以数组传递，不调用 shell；采集目录随机、任务结束清理。
- 单实例同时仅一项仿真，时间上限 15 秒、探针上限 4、深度上限 1024。
- 实际 flag 及私有 ROM 不进入选手包，官方脚本与 WP 不进入 Docker 镜像。

这些是本实现的检查范围，不等同于对整个宿主机或平台的安全审计。

## 赛前调整

当前设计偏重原理理解，熟悉 HDL 和 VCD 的队伍可能快速定位状态机。
若需进一步加难，可引入有实际用途的突发事务或不同采样时钟域，
并同时更新公开 RTL、手册、参考解和测试，验证难点仍有可推导路径。
不要仅靠隐藏接口文档、极短超时或大规模枚举制造难度。
